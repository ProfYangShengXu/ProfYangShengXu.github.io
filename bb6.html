Small-model Multi-Agent Harness

面向小模型的多智能体运行时。用调度、分层与 harness 设计补足小模型的能力短板， 承担大批量、中等复杂度的任务。

是什么

一个以小模型为核心的多智能体运行时。它不试图让单个模型变强， 而是把任务拆开、分层、分派，让多个小模型协作完成一件本来需要强模型才能做完的事。

做什么

接收批量任务，将其解析为结构化契约，按依赖切分后分派给多个智能体执行， 并逐块判定产物是否达标。适合处理重复量大、但单个任务复杂度中等的工作 —— 这类任务用强模型成本过高，用单次调用的小模型又难以保证质量。

为什么这么做

现在主流的 agent harness 基本都以强模型单智能体为中心：一个足够强的模型加一套工具， 能力上限很高，但代价是每次调用的成本也高。这类设计在复杂、长尾、需要判断力的任务上是对的， 可它并不适合另一类工作 —— 数量大、模式重复、单件难度不高、但要的是稳定产出。

小模型在单次调用下确实做不好这类任务，问题通常不在知识量，而在一次要它同时兼顾的事太多： 既要覆盖全，又要结构对，还要质量稳。强度不够时，它会漏、会偏、会在细节上塌陷。

bb6 的思路是不要求模型一次做对所有事：

  • 任务分层 —— 把一次大判断拆成若干小判断，每一层只让模型面对它能胜任的复杂度。
  • 多智能体调度 —— 由运行时负责分工、串接与回收，而不是让一个模型在上下文里独自记住全部约束。
  • harness 承担约束 —— 该由代码保证的东西（覆盖、格式、依赖顺序、失败判定）不交给模型去自觉遵守。

换言之：用系统设计补足模型智力，而不是靠提示词要求它表现得更聪明。

和主流 harness 的关系

不是替代关系，是补位关系。

强模型单智能体 harnessbb6
核心模型强模型小模型（4B 级）
擅长复杂、长尾、需要判断的任务量大、模式重复、复杂度中等的任务
单次成本高低
能力来源模型本身调度 + 分层 + harness 设计
失败形态偶发但难定位逐块具名，指出哪一块没过

两者面向的是不同的任务分布。选哪一个，取决于任务量大不大、单件难不难、以及能不能接受按次数计费。

评测

对小模型场景下的横向评测正在进行。目标是回答一个问题： 在同一批任务、同一个 4B 级模型下，本系统相对其他 agent harness 的表现差异有多大。

评测集包括 JD 信息采集、代码任务等需要大量重复执行的任务族， 每组跑足够多次以区分真实差异与随机波动。数据量与质量达标后会在这里公布读数。

在此之前不放单次案例 —— 单个案例说明不了系统， 反而容易把偶然当结论。
